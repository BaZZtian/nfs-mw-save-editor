# Raw Xbox 360 / nfsmw-nx save support

This backend extension targets the v1.5.0 desktop editor. It adds a
reversible serialization adapter that connects raw Xbox 360 saves used
by nfsmw-nx to the existing save-editing engine.

**Experimental:** support is limited to the raw native layout described here.
Compatibility across every native version and PC/Xbox part index has not been
established. Keep an independent known-good backup when editing saves.

## Supported inputs

| Input | Size | Serialization |
| --- | ---: | --- |
| Existing Most Wanted PC v1.3 save | 63,596 bytes (`0xF86C`) | Original little-endian implementation |
| Raw Xbox 360 / nfsmw-nx save | 62,688 bytes (`0xF4E0`) | `MC02`, big-endian header, version `0x10D`, gameplay version 8 |

Support is for the raw save payload, including extensionless profile files.
It does not add an Xbox STFS container extractor, encryption, or a universal
converter for every game/platform save version.

The native format is detected when `SaveFile` is constructed or loaded. An
unknown native header or serialization version is rejected before writing.
Format selection is automatic for supported inputs.

## Edit the authoritative runtime save

`saves/<profile>/actual` and `saves/<profile>/anterior` are **directories of
automatic copies**, not the content containers from which the game loads.
Editing either or both copies does not import the edit into the active save.

With the default Switch paths, the authoritative payload is:

```text
<NRO folder>/nfsmw/<XUID>/454107D9/00000001/<profile>/<profile>
```

The last component is the extensionless save file. Use the existing XUID and
profile directories generated by this installation. Leave `Headers` and
`<profile>.header` intact. A configured `user_data_root` override can change
the prefix; the port's `[guardado]` open/close log also records its real path.

Fully close the game and shut down the Switch before editing the SD card.
Open that authoritative file, stage changes, use `Apply (memory)`, then
`Save + backup`. Reopen the same file in the editor before returning the card
to the Switch to verify that the edited values and integrity were persisted.

The port's `ContentManager::CloseContent` calls `CopiaParaElUsuario`: it
deletes the previous `anterior`, moves `actual` to `anterior`, and copies the
runtime container to a new `actual`. An editor backup placed in either copy
directory can therefore move and disappear during later container closes.
Keep any manual long-term backup on the PC.

MD5/DATA becoming BAD immediately after an in-memory edit is expected until
checksums are repaired. `Fix checksums` does that in memory; `save()` also
repairs them automatically. Repairing checksums in a copy directory does not
change which file the game loads.

Port path handling is defined in these sources at commit
`4e3ffc24fe80285189f2cea601606c529d5f1b97`:
[content_manager.cpp](https://github.com/StevensND/nfsmw-nx/blob/4e3ffc24fe80285189f2cea601606c529d5f1b97/sdk/src/system/xam/content_manager.cpp),
[rex_app.cpp](https://github.com/StevensND/nfsmw-nx/blob/4e3ffc24fe80285189f2cea601606c529d5f1b97/sdk/src/ui/rex_app.cpp) and
[filesystem_posix.cpp](https://github.com/StevensND/nfsmw-nx/blob/4e3ffc24fe80285189f2cea601606c529d5f1b97/sdk/src/core/filesystem_posix.cpp).

## Adapter modules

| File | Role |
| --- | --- |
| `core/savefile.py` | Factory dispatch to `SwitchSaveFile`; existing PC edit methods stay intact |
| `core/switch_format.py` | Native detection, typed conversion, native persistence and integrity |
| `core/career_progress.py` | Normalize native input for the original career dashboard parser |
| `core/career_transplant.py` | Accept the native size when reading the current Blacklist stage |

The adapter uses Python's standard library and adds no runtime dependency.

## Representation and persistence

`SwitchSaveFile` presents the existing `SaveFile` API. Its private PC engine
works on a canonical little-endian view, so the original garage allocator,
Junkman inventory, tuning, car build export/injection and career transplant
logic remain in use.

The public `data` buffer remains a native 62,688-byte `bytearray`. This matters
because the original GUI compares it with disk bytes to determine whether
changes are unsaved and implements staged `Apply (memory)` and disk reload.
Direct modifications of that public buffer are adopted before further edits.
Delegated editor calls synchronize their changes into the same bytearray
before returning, so a held `data` reference stays valid across setters and
checksum repair. Cached delegated methods also adopt external edits at call
time. Conflicting raw writes and unsynchronized changes through a retained
private-engine subobject are rejected explicitly rather than silently losing
either edit; synchronize through `save.data` before such mixed direct use.

On serialization, only changed, named regions are translated into a copy of
the original native file. Owned-car, customization and pursuit tables are
compared and written back one record at a time, so padding in unchanged
neighbour records is not normalized. Unknown bytes, unedited regions, the console-only
prelude and platform-specific tail are retained. A valid no-edit save is
byte-identical after saving. Loading alone never modifies the input file.

The private canonical representation is never written to disk. The native
save path repairs the tail MD5 and all three big-endian EA CRC32 values and
uses the original backup filename convention. `save()` backs up the original
disk file before writing the edited native file. Gameplay conversion also
repairs the inner 16 KiB gameplay-section MD5.

## Typed regions

Offsets are absolute and hexadecimal. The offset difference is **8 bytes
(64 bits)** for the vehicle tables, not an 8-bit shift. Byte order is a
separate issue: reverse numeric fields according to their types, never the
whole save or every arbitrary four-byte group.

| Region | PC offset | Native offset | Conversion |
| --- | --- | --- | --- |
| Gameplay section + inner MD5 | `0034` | `0034` | Structured gameplay arrays and persistent activities |
| Active car pointer | `4034` | `4034` | Full `u32` |
| Current Blacklist stage | `4038` | `4038` | Byte |
| Money | `4039` | `4039` | `u32` |
| Difficulty, special flags, SMS | `403D` | `403D` | Mixed `u16`, full `u32` flags, byte fields and SMS order `u16` |
| Race results and unlock belt | `42B9` | `42B9` | Typed race results; unlock bytes retained |
| 63 reward-marker slots | `5739` | `5739` | Three `u32` per 12-byte slot |
| Profile alias | `5A31` | `5A31` | ASCII bytes |
| 119 owned-car records | `6219` | `6221` | Four `u32`, byte links, platform padding |
| 44 customization records | `9CCD` | `9CD5` | Part indices `u16`, performance/masks/floats `u32`, byte handle |
| 25 pursuit records | `E2ED` | `E2F5` | Heat `float32`, bounty `u32`, counters `u16`, byte impound fields |
| Sold-car pursuit history | `E865` | `E86D` | Bounty `u32` and counters `u16` |

Known padding is normalized between native `AA` and the PC editor's `CD`
sentinels inside the private view and translated back on a changed record.
Unknown padding values are retained.

Two legacy PC career-transplant spans (`0x5B41` and `0x5B62..0x5B63`) have no
verified console counterpart. The canonical view leaves these undocumented
PC settings neutral; native bytes at those positions are preserved during a
stage transplant. This is an intentional format boundary, not a claim that
those console bytes were decoded.

Diagnostic offsets exposed by original editing methods refer to their
canonical PC tables. A raw hex editor must use the native offsets above.

## Gameplay serialization and packed Lua values

The gameplay section is converted field by field: version/count header,
aligned persistent records, timers, milestone types, milestones, speed traps,
gates, hiding-spot bitset, race-bin statistics, pending SMS and footer keys.
Array alignment is relative to the start of the gameplay section.

Each persistent record (including alignment), fixed-size array, hiding-spot
bitset, race-bin statistics span and 32-byte aligned footer is bounds-checked
against the 16 KiB section before that span is walked. This includes gates
and pending SMS; oversized counts cannot cause an unbounded walk. `_reverse`
rejects negative and out-of-range spans before changing any bytes.

`TableVar` bitfields have different byte layouts on Xbox and PC. The adapter
translates their type, boolean, packed, key and valid fields and reverses only
unpacked numeric payloads. Packed identifier payload bytes remain opaque.

Packed identifiers can contain internal zero bytes. The adapter finds a
complete alternating key/value stream, prefers the segmentation retaining
the most complete entries, and rejects equally complete ambiguous parses.
This parsing rule is inferred and checked against the supplied native save
and all 30 bundled career gameplay blocks. It is not an independently
recovered implementation of `PackIdentifier`; unrepresented activity data
may require additional schema work. It must not silently guess an ambiguous
payload.

Schema evidence comprises the original editor sources, a privately supplied
raw native save, and the `GManager`, `GActivity`, `TableVar`,
`FECustomizationRecord` and `FECarRecord` type definitions in
[dbalatoni13/nfsmw](https://github.com/dbalatoni13/nfsmw) at commit
`1f2cdd7996791c81a580b3f7b36b44d4f9f6719c`.
No decompilation source files or personal saves are bundled with this patch.

## Validation

Run the format and regression checks from the repository root with the
project dependencies and pytest installed:

```bash
PYTHONPATH=nfs_mw_save_editor QT_QPA_PLATFORM=offscreen \
  python -m pytest nfs_mw_save_editor/tests/test_switch_format.py \
  nfs_mw_save_editor/tests/test_switch_review.py -q
```

The synthetic fixtures are generated at test time. Tests cover native byte
order, unsupported versions, gameplay array and footer bounds, held mutable
buffers, record-level padding preservation, backup contents and integrity
repair. The gameplay-array golden test constructs expected bytes directly,
independently of `game_region()`.

Set `NFS_MW_SWITCH_TEST_SAVE` to the path of a raw native save to enable the
optional private-fixture test. Without that variable, the optional test is
skipped. Test writes are confined to temporary copies.

The UI verification script opens a native save, visits all eight pages,
applies an edit, saves with a backup and reloads the disk file. It checks that
the supplied input remains unchanged and accepts the application's
confirmation dialogs automatically within the test:

```bash
QT_QPA_PLATFORM=offscreen \
  python nfs_mw_save_editor/tools/verify_switch_ui.py /path/to/raw/save
```

In Windows PowerShell, use the interpreter from the project environment:

```powershell
.\.venv\Scripts\python.exe .\nfs_mw_save_editor\tools\verify_switch_ui.py "C:\path\to\native-save"
```

The save paths above are placeholders. Replace them with a raw native save
file. Automated round trips establish serialization behavior and integrity;
acceptance of edited gameplay data also requires testing in the game.
